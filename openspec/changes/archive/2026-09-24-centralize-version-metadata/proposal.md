# 提案：集中管理版本元数据

## Why

当前包版本同时出现在 `package.json`、`package-lock.json`、CLI 源码、安装示例和多份文档中。修改版本时容易遗漏 CLI 输出或把历史发布快照误写成当前状态，需要明确权威来源并增加自动检查。

## What Changes

- 以 `package.json` 的 `version` 作为当前源码包版本的唯一人工维护值，让 `wk --version` 从已安装包的清单读取版本。
- 为包清单、锁文件和 CLI 版本输出建立自动一致性检查，并接入现有 CI；发布标签只在维护者决定发布里程碑时检查和创建。
- 去除当前安装示例中的固定包文件名；把文档中的版本数字明确区分为有日期的历史验证记录与需要实时查询的当前状态。
- 记录版本号、Git 标签、npm registry 三者的职责和发布前核对步骤。Git 提交与推送仍按每项 OpenSpec 工作执行，不自动改版本、打标签或发包。

## 能力

### 新增能力

- `version-consistency`：CLI 报告与包清单一致的版本，项目检查能发现包清单、锁文件和可运行 CLI 的版本分歧，并在发布前核对标签。

### 修改能力

无。当前 `openspec/specs` 尚无相关能力规格。

## 影响范围

涉及 CLI 版本来源、npm 脚本与 CI、相关测试，以及 README 和当前开发/验证文档。历史 CHANGELOG 条目、带日期的发布验证记录、已发布 npm 包和既有 Git 标签保持原样；不引入新的运行时依赖或改变 `wk` 命令接口。
