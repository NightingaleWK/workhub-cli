# Design

## Context

见 [proposal.md](proposal.md)。当前根配置、执行日志、写锁、Trellis 任务入口和代理指令标记由多个模块分别引用；文档和测试也包含这些路径。真实账号、署名及 npm 锁文件校验串是外部标识。

## Goals / Non-Goals

**Goals:** 让生成、读取、校验使用同一组 WorkHub 标识；在隔离目录验证安装与正式任务全流程；让源码与当前说明一致。

**Non-Goals:** 改动仓库外的用户工作空间、包版本、Git 标签或 npm 已发布内容。

## Decisions

1. 在现有模块中直接替换路径、环境变量、任务文件名和区块标记。项目没有外部使用者，因此保持单一路径与单一名称，避免双路径读取、搬运逻辑和额外状态。
2. 将生成与校验同时更新：`install`、`init`、`check`、预览、Trellis 模板和 CLI 输出必须引用同一名称。现有数据结构的字段与版本保持不变，因为此工作只改变存放位置和生成名称。
3. 删除仓库中与当前约定冲突的归档说明和过时文档，保留 Git 提交历史。重写当前文档时只描述现行用法。外部账号、许可证署名和依赖完整性校验值原样保留。
4. 使用临时 WorkHub 根目录和 `WORKHUB_CONFIG_PATH` 做全流程验收，再核对 `npm pack` 内容；所有真实用户目录保持只读。

## Risks / Trade-offs

- [生成端与检查端名称不一致] → 以测试覆盖安装、初始化、任务文件和 `check`，并在打包安装后进行临时目录验收。
- [误改外部标识或用户数据] → 只编辑仓库文件，扫描结果区分真实账号与校验串，测试始终使用隔离根目录。
