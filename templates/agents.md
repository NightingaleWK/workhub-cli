# WorkHub 工作约定

- 本目录仅保存 Trellis 管理信息，不是代码或业务产物目录。
- 根据用户给出的工作编号，在 `.trellis/tasks` 查找对应任务，先读取 `workhub-context.md` 和 `workhub-handoff.md`，再读取相关业务 README。
- 多个任务并存时不得擅自推断唯一当前任务；不要为本工具切换共享任务状态。
- `workhub-context.md` 中的根目录相对路径用于定位 WorkHub；各组成部分路径相对于该根目录。记录中的工作日期不等于 Trellis 任务文件夹前缀日期。
- 所有程序、脚本、测试和部署代码写入对应 code 仓库；业务资料、临时分析产物和验证证据写入本次 work 目录。未启用所需组成部分时先说明缺口。
- operations 仅按用户授权范围更新已验证知识；archive 默认只读。
- 进入附加仓库工作前，显式读取目标仓库及目录适用的 AGENTS.md，检查并保留已有修改。
- 执行脚本、测试和 Git 命令时明确指定目标目录，不默认使用当前 Trellis 仓库。
- 以文件、当前证据和交接恢复进度，区分已验证、未验证、失败与推测，不把旧资料当成当前事实。
- 实质进展后更新对应 `workhub-handoff.md`，记录变化、验证与证据、遗留、下一步和相关代码版本。它是该任务的交接入口，已有正式交接时在此引用，不重复维护。
- 不自动提交、推送、部署、归档或覆盖用户文件；遵循当前用户实际授权。
